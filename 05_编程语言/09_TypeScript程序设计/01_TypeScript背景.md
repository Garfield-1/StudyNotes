# TypeScript 语法

## 一、TypeScript 背景

### 1.1 什么是 TypeScript

`TypeScript`（简称 `TS`）是由 **微软（Microsoft）** 开发并开源的一门编程语言，它是 **JavaScript 的超集**（`Superset`），即在 `JavaScript` 的基础上扩展了额外的语法特性，最核心的扩展就是**静态类型系统**。

- 任何合法的 `JavaScript` 代码都是合法的 `TypeScript` 代码
- `TypeScript` 代码无法直接运行，需要通过编译器（`tsc`）**转译（Transpile）** 为 `JavaScript` 后才能执行
- 转译时可指定目标 `ES` 版本（如 `ES5`、`ES6`、`ESNext`），从而兼容不同运行环境

### 1.2 发展历程

| 时间              | 里程碑                                                       |
| ----------------- | ------------------------------------------------------------ |
| `2012` 年 `10` 月 | `TypeScript 0.8` 正式发布，由微软主导设计， `Anders Hejlsberg`（`C#` 之父）领衔开发 |
| `2014` 年         | `TS 1.x` 时期，引入 `ES6` 特性支持，社区生态逐步建立         |
| `2016` 年         | `TS 2.0` 发布，引入更强的类型推断、联合类型增强等特性        |
| `2018` 年         | `TS 3.0` 发布，项目引用、元组类型增强，成为大型前端项目主流选择 |
| `2020` 年         | `TS 4.0` 发布，可变元组、模板字面量类型等高级类型能力增强    |
| `2023` 年         | `TS 5.0` 发布，性能大幅提升，原生支持装饰器（`Decorators`）  |
| 至今              | 持续迭代，已成为前端、`Node.js`、`Electron` 等项目的标准技术选型 |

### 1.3 诞生背景与动机

`JavaScript` 是一门**动态弱类型语言**，语法灵活、上手快，但随着项目规模扩大，暴露出以下问题：

1. **类型错误只能在运行时暴露**：如 `undefined is not a function` 等错误，开发阶段无法提前发现
2. **大型项目难以维护**：函数参数、返回值含义不明确，重构风险高
3. **团队协作成本高**：缺少接口契约，代码依赖口头约定和文档
4. **IDE 支持弱**：无类型信息，代码提示、自动补全、跳转定义能力有限

微软为解决这些问题，设计了 `TypeScript`：在保留 `JavaScript` 灵活性的同时，引入**编译期静态类型检查**，让开发大型应用更可控。

## 二、TypeScript 与 JavaScript 的对比

| 对比项       | JavaScript                  | TypeScript             |
| ------------ | --------------------------- | ---------------------- |
| 类型系统     | 动态弱类型                  | 静态类型（可选注解）   |
| 错误发现时机 | 运行时                      | 编译期                 |
| 运行方式     | 浏览器 / `Node.js` 直接执行 | 需编译为 `JS` 后执行   |
| `IDE` 支持   | 有限                        | 强（智能提示、重构）   |
| 学习成本     | 低                          | 略高（需学习类型系统） |
| 适用场景     | 小型脚本、快速原型          | 中大型项目、团队协作   |
